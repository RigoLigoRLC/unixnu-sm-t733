# 75：A642L 的 GMEM 红蓝通道回归

用户报告 74e 卡顿没有明显改善，红蓝通道异常扩大到壁纸和图标。
本轮修复针对颜色，保留该性能观察。74e 的 GPU 和显示任务完成记录见
[74 迁移记录](GPU_UPSTREAM_REBASE_74_2026-11-01.md)。

## 源码原因与修复

新增上游 GMEM 补丁将非 mutable 图像在系统内存端的 COLOR_SWAP 清为 WZYX。
在 A6xx 的原有格式实现中，线性 BGRA 使用 WXYZ，GMEM 纹理读取使用 WZYX；
将线性目标的交换位一并清除改变了写回内存的红蓝顺序。A642L 的常规图像会进入
这个非 mutable 分支。73c 到 74e 的 DPU 驱动和系统 BGRA8 格式策略没有变化。

core `12729b7b1d52cf7056c30625786c08c9763345ac` 新增并登记第 27 层补丁
`patches/mesa/turnip-a6xx-gmem-linear-color-swap.patch`。
`tu_gmem_transfer_swap_fixup` 接收芯片模板参数，A6XX 保留图像视图提供的寄存器值；
四个调用点同步传入 CHIP。A7 及后续芯片沿用上游处理。
74e 的 lazy transient image 登记修复、memoryless、硬件一致性和采集功能保留。
