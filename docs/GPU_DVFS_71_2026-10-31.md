# SM-T733 GPU DVFS

2026-10-31。用户要求在已实测的 70a 复制优化和关机修复基础上尝试 GPU DVFS，并指定此前调查的小米手机实现作为参考。当前实施位于 `unixnu-sm-t733`；Apple3 分支保持原有引用。

## 参考来源

- 手机参考是 [Data A Live](https://github.com/ShueiTsuki/data-a-live)，机型为小米 17 Pro，代号 pandora，SM8850 / Adreno 840。本地最初读取的提交为 `a4173581595e63808a1c8f0742e7da838ecf27f6`，调频代码位于 `wsl/pandora_gpu.c`，策略改进补丁为 `0198-pandora-gpu-dcvs2.patch`。
- 本轮已获取原仓库 `db88a20` 和接续仓库 [yechenan/data-a-live](https://github.com/yechenan/data-a-live) 的 `6547194`。两者的 `pandora_gpu.c` 相同。选档策略仍采用 16 ms 周期、50% busy 目标、快速升频、四个低负载窗口后降一档、80 ms 空闲回初始档和 50 ms 活动 boost。后续新增机身温控上限；本机使用自己的 TSENS 输入和有效频率表。
- 本机硬件程序依据 Samsung SM7325 内核 `36b842cf1fc87a989dcc8158a142d7575cee41c1` 的 `adreno_a6xx_gmu.c`、`adreno_a6xx_rpmh.c` 和 `yupik-gpu.dtsi`。原厂设备公开的有效频率为 315/450/550 MHz；运行 FDT 的 DDR 类型为 7。
- 本轮已取得官方 UniXNU `f0721e9`。相对当前固定的 `066c8d8`，更新涉及设备目录和文档，GPU 运行时代码没有变化。

## 调档与测量

GPU 启动请求保持 315 MHz。三个有效档使用原厂电压等级 64/128/192 和 DDR7 带宽表索引 3/6/9。GMU 收到同一 HFI 请求中的频率及带宽索引后返回 ACK；驱动将确认后的频率记录到采集数据。

busy 来自 GMU 的 19.2 MHz XO0 忙碌计数，采用 high/low/high 读取。现有 29 路 GPU 硬件计数和 shader 活动继续通过受 OOB 保护的采集路径读取。GPU 调频不改变 Perfetto 使用的 19.2 MHz 时间戳换算。

原有 trace ABI v1 保持结构尺寸，状态结构最后一个保留字段改为 `performance_count`，新增 section 5 保存最多 4096 个 64 字节记录。主机文件为 `performance.bin`，顺序如下：

```text
<3Q4Ii5I
timestamp_ns, busy_ticks, interval_ns,
acknowledged_hz, requested_hz, bandwidth_index, thermal_cap_hz,
temperature_millic, thermal_valid_mask, thermal_flags,
busy_permille, flags, vote_status
```

`flags` 的位 0..5 分别表示 busy 有效、活动 boost、固定频率、GPU 工作待完成、频率请求变化及温控限制。`timestamp_ns` 为本轮处理完成时的主机单调时钟；有调档时为 ACK 完成时间。`busy_ticks` 和 `interval_ns` 描述刚读取的采样窗口。主机将 busy 显示为样本点，并保留窗口长度供分析。

Perfetto 显示 GMU 确认频率、请求频率、带宽索引、温控上限、busy、GPU 温度和 boost 状态。旧包保留字段为 0，仍能导出已有 trace。采集溢出计入 `sample_dropped`，不得据启用状态宣布测量成功。

## 对照基线

70a 在固定 315 MHz 时，2732x2732 BGRA 大复制 645 个样本平均 4.478 ms，每层一个完整矩形 draw；render pass 占覆盖充分任务所记录三大阶段的约 72%。原始数据位于工作区 `logs/gpu-perfetto-70a-runtime-1/`。本轮使用同样的 60 秒采集流程，按实际频率及相同操作类型比较 GPU 执行时间。

70a 已实测正常关机，下一次替换其启动 FAT 时保留备份。构建、刷入及本轮实测结果另按实际完成状态补充。
